# 13. Quality attributes

The architecture covers every quality attribute in [3. Requirements](03-requirements.md);
SOC 2 checks some of them, not all ([12. SOC 2 readiness](12-soc2-readiness.md)). One table
for where each is designed and what has actually been measured, so a figure in a decision
record is never mistaken for a property of the whole system, and a design is never
mistaken for a measurement.

## Disaster recovery

RTO and RPO by component and failure, not one number for the whole platform:

| Component | Failure | RTO / RPO | Mechanism | Measured? |
|---|---|---|---|---|
| Product database (RDS) | an availability-zone is lost | AWS-documented Multi-AZ failover | RDS Multi-AZ, the vendor's own mechanism | not measured here |
| Product database (RDS) | a bad write | point-in-time recovery | RDS point-in-time recovery | not measured on RDS itself; the same mechanisms (leader failure, replica rebuild, point-in-time restore) are measured on a self-run Patroni cluster in [postgres-ha-lab](https://github.com/technobasant/postgres-ha-lab): promotion observed in 10–20 s after killing the leader, a replica rebuilt from backup in about 5 s, 5 of 5 rows recovered by point-in-time restore. Stated plainly: that is a different deployment of the same mechanisms, not this company's RDS instance |
| Platform tables | a bad write found within 7 days | RTO within Q9's one hour | `RESTORE` to a version in the last 7 days ([0015](../decisions/0015-restore-points.md)) | **365 of 365** days back after `RESTORE TABLE`, following an `INSERT OVERWRITE` of one day that left 1 (a sibling lab's measurement, same mechanism) |
| Platform storage | a bucket, key or Terraform mistake destroys the table storage | RPO a day, RTO hours | restore from the off-account AWS Backup vault, then re-apply the erasure log before anything reads the restored data ([0015](../decisions/0015-restore-points.md)) | not measured |
| CDC | the replication slot is lost (an RDS failover or major-version upgrade) | RPO the size of the gap, logged; RTO the time to re-snapshot the captured tables | the re-snapshot runbook ([9. Operations](09-operations.md#the-cdc-slot-stalls-or-is-lost)) | not measured; depends on table size at the time |
| The region | the EU region itself is lost | out of scope | [the brief](01-brief.md#out-of-scope) constrains everything to one region; the off-account backup vault is in the same region, so a regional loss is an accepted risk, not a covered one — stated plainly, not hidden in a table cell | not applicable |
| The platform vendor | a regional service outage | dashboards show yesterday's data; the product is unaffected | this is what moving analytics off the product's database buys ([0001](../decisions/0001-analytics-off-the-product-database.md)): a vendor outage degrades reporting, not the product | not measured |

## What is not covered

Multi-region operation and data residency beyond the one EU region; machine learning beyond
the stage-3 assistant; replacing the BI tool. All three are out of scope in
[1. Brief](01-brief.md#out-of-scope), and nothing in this document or the control matrix
quietly brings them back in.
